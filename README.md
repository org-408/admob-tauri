# admob-tauri

A [Tauri 2](https://tauri.app) plugin for [Google AdMob](https://admob.google.com) on iOS and Android: a port of
[`@capacitor-community/admob`](https://github.com/capacitor-community/admob) 8.3.0 that keeps its API (same method
names, arguments, results and events), so an app moving from Capacitor to Tauri Mobile only changes an import.

Banner, interstitial, rewarded, rewarded interstitial and app open ads, native ads, the Google UMP consent flow
(including the privacy options form) and iOS App Tracking Transparency.

Status: **v0.1.1, not published to crates.io / npm yet.** Use it from git for now (see [Install](#install)).

**Plan:** the intent is to publish `admob-tauri` to crates.io and npm. Before that, the Android side still has to be run on
an emulator or device, and the consent form, ATT prompt, rewarded and native ads checked on real devices. Until then
the plugin is a pre-release. See [Status and roadmap](docs/ROADMAP.md).

This is an independent community project. It is not affiliated with or endorsed by Google, the Tauri Programme or the
Capacitor Community. It is not an official Tauri plugin.

## How it is built

The native code is upstream's: the Swift and Kotlin/Java sources of `@capacitor-community/admob`, calling the Google
Mobile Ads SDK and the User Messaging Platform exactly as upstream does. Only the bridge differs: Capacitor's
`CAPPluginCall` / `PluginCall` becomes a small shim over Tauri's `Invoke`, and Capacitor's `notifyListeners` becomes
Tauri's `trigger`. The TypeScript API (`guest-js/`) is upstream's `src/` unchanged apart from import paths. Rust only
passes each command through. See [docs/TECH-NOTES.md](docs/TECH-NOTES.md).

| Upstream                                             | Here                                                                       |
| ---------------------------------------------------- | -------------------------------------------------------------------------- |
| `src/**/*.ts`                                        | `crates/admob-tauri/guest-js/` (same files; `index.ts`, `bridge.ts` new)   |
| `ios/Sources/AdMobPlugin/**`                         | `crates/admob-tauri/ios/Sources/AdmobTauri/` (+ `PluginCall.swift`)        |
| `android/src/main/java/.../admob/**`                 | `crates/admob-tauri/android/src/main/java/` (+ `PluginCall.kt`, `AdmobPlugin.kt`) |
| `registerPlugin('AdMob')`, `@PluginMethod`           | Tauri commands (`src/commands.rs`, `build.rs`, `permissions/`)             |

## Install

Not on crates.io / npm yet. Until then, from git:

```toml
# src-tauri/Cargo.toml
[dependencies]
admob-tauri = { git = "https://github.com/org-408/admob-tauri", tag = "v0.1.1" }
```

```sh
npm install github:org-408/admob-tauri#v0.1.1   # TypeScript API (the package is in crates/admob-tauri)
```

Register the plugin and allow its commands:

```rust
// src-tauri/src/lib.rs
tauri::Builder::default().plugin(admob_tauri::init())
```

```json
// src-tauri/capabilities/default.json
{ "permissions": ["core:default", "admob-tauri:default"] }
```

`admob-tauri:default` allows every command. Each command also has its own permission (`admob-tauri:allow-show-banner`,
...), listed in `crates/admob-tauri/permissions/autogenerated/reference.md`.

### iOS

- iOS 15.0 or later (`bundle.iOS.minimumSystemVersion`).
- **Xcode 27 or later** to build. The Google SDKs are binary frameworks, and with Xcode 26.6 the plugin's Swift package fails to
  build (`no such module 'GoogleMobileAds'`: swift-rs builds it for the macOS host there). Tested with Xcode 27.
- `src-tauri/Info.ios.plist` needs your AdMob app ID, the SKAdNetwork identifiers and the tracking message
  ([Google's guide](https://developers.google.com/admob/ios/quick-start)):

```xml
<key>GADApplicationIdentifier</key>
<string>ca-app-pub-xxxxxxxxxxxxxxxx~yyyyyyyyyy</string>
<key>NSUserTrackingUsageDescription</key>
<string>This identifier is used to deliver personalized ads to you.</string>
<key>SKAdNetworkItems</key>
<array><dict><key>SKAdNetworkIdentifier</key><string>cstr6suwn9.skadnetwork</string></dict></array>
```

The Swift package depends on `swift-package-manager-google-mobile-ads` and
`swift-package-manager-google-user-messaging-platform`; Tauri builds it with Swift Package Manager.

### Android

Add your AdMob app ID to the app's `AndroidManifest.xml` (`src-tauri/gen/android/app/src/main/`), inside
`<application>` ([Google's guide](https://developers.google.com/admob/android/quick-start)):

```xml
<meta-data
    android:name="com.google.android.gms.ads.APPLICATION_ID"
    android:value="ca-app-pub-xxxxxxxxxxxxxxxx~yyyyyyyyyy" />
```

`minSdk` 24 or later. The plugin adds the `INTERNET` and `ACCESS_NETWORK_STATE` permissions.

## Usage

```ts
import { AdMob, BannerAdPosition, BannerAdSize, BannerAdPluginEvents } from 'admob-tauri';

await AdMob.initialize();

const info = await AdMob.requestConsentInfo();
if (info.isConsentFormAvailable && info.status === 'REQUIRED') await AdMob.showConsentForm();

AdMob.addListener(BannerAdPluginEvents.SizeChanged, ({ height }) => {
  document.body.style.paddingBottom = `${height}px`;
});
await AdMob.showBanner({
  adId: 'ca-app-pub-3940256099942544/6300978111', // Google's test unit
  adSize: BannerAdSize.ADAPTIVE_BANNER,
  position: BannerAdPosition.BOTTOM_CENTER,
});
```

The API is the one of `@capacitor-community/admob`: see its
[documentation](https://github.com/capacitor-community/admob#readme). Always develop with Google's
[test ad units](https://developers.google.com/admob/android/test-ads), never your real ones.

### What differs from Capacitor

- `import { AdMob } from 'admob-tauri'` instead of `'@capacitor-community/admob'`. Names, arguments, results,
  events and enums are the same.
- `addListener` returns `Promise<PluginListenerHandle>` as in Capacitor; it is built on Tauri's `addPluginListener`.
  It needs the `admob-tauri:allow-register-listener` / `allow-remove-listener` permissions (in `default`).
- `PluginListenerHandle` is exported from `admob-tauri` (Capacitor exports it from `@capacitor/core`).
- Off iOS and Android (a desktop webview, a browser), the calls answer like upstream's web stand-in (they log and
  resolve); no ads are shown.
- Android: the banner is added to the activity's content view (Tauri's WebView is the content view itself; upstream
  adds it next to a `CoordinatorLayout`). There is no Capacitor `SystemBars` plugin in Tauri, so the banner's
  `insetsHandling` follows the "disable" behaviour.
- Rejections carry `code` and `message` (and `data` when upstream sends it) on an `Error`, as `CapacitorException` does.

## Testing

`examples/admob-tester` is a Tauri app that calls the plugin with Google's test ad units: one button per call, and
"Run checks" runs those that need no tap and writes `report.json` (Android: also `adb logcat -s admob-tester`).

```sh
npm install
cd examples/admob-tester
npx tauri ios init && npx tauri ios dev "iPhone 17 Pro"     # iOS Simulator
npx tauri android init && npx tauri android dev             # Android emulator
```

Checks that run on every pull request ([CI](.github/workflows/ci.yml)): `cargo fmt`, `clippy -D warnings`,
`cargo test`, `npm run verify` (format, build, type-check, tests), the Android Kotlin/Java unit tests, and, on
`develop`, the iOS Swift build. `__tests__/apiParity.test.ts` checks that every method and event of
`@capacitor-community/admob` exists on every layer (TypeScript, Rust command, permission, Swift, Kotlin).

## Following upstream

A daily workflow opens a pull request when `@capacitor-community/admob` releases a new version, moving the pins
(upstream's version and the Google Mobile Ads / UMP SDK versions it uses). If upstream's API changed, the parity
test fails on that pull request and the change is ported on its branch. See [docs/UPSTREAM.md](docs/UPSTREAM.md).

## Contributing

Issues and pull requests are welcome. Work happens on `develop` (`feature/T<issue>-<name>` branches); please keep
the native code as close to upstream as possible so that upstream changes stay easy to follow, and run
`npm run verify` and `cargo test` before opening a pull request.
