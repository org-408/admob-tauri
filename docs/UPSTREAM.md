# Following @capacitor-community/admob

This plugin is a port, so most of its value is staying in step with upstream. Three things are tracked.

| What | Where we hold it | How a change is noticed |
| ---- | ---------------- | ----------------------- |
| Upstream's version (its API and native code) | `devDependencies["@capacitor-community/admob"]` in `package.json` (exact) | `track-upstream` workflow opens a PR; `__tests__/apiParity.test.ts` fails if methods or events were added or removed |
| Google Mobile Ads SDK and User Messaging Platform versions | `ios/Package.swift` (Swift package pins), `android/build.gradle.kts` (Gradle) | the same PR: `scripts/track-upstream.mjs` copies the pins upstream states at its release tag |
| Upstream's Swift / Kotlin / Java code | `crates/admob-tauri/ios`, `android` | read the diff between upstream's tags (below) and port it by hand |

## The daily workflow

`.github/workflows/track-upstream.yml` runs `node scripts/track-upstream.mjs` every day. It compares our pins with the
latest `@capacitor-community/admob` release (npm `latest`, the files at the release's git tag). If anything differs it
opens `chore/upstream-<version>` with the pins moved (`--apply`) and a pull request to `develop`.

- A pull request created with `GITHUB_TOKEN` does not start CI. The workflow therefore starts `ci.yml` on the branch
  with `gh workflow run` (`workflow_dispatch` is allowed for `GITHUB_TOKEN`); the result shows on the branch's
  commit. To get the normal pull-request checks, add a `TRACK_UPSTREAM_TOKEN` repository secret (a fine-grained token
  with contents and pull-requests write); the workflow uses it when present.
- Run it by hand with "Run workflow", or locally: `node scripts/track-upstream.mjs` (look),
  `--version <x.y.z>` (look at a given release), `--apply` (move the pins).

## Porting an upstream change

1. Let the pull request fail: `apiParity` names the missing or removed method or event.
2. In an upstream clone: `git diff v<old>..v<new> -- src ios android`. Copy `src/` changes to
   `crates/admob-tauri/guest-js/` (fix relative imports to end in `.js`; `capacitor.ts` and `web-plugin.ts` stand in for
   `@capacitor/core`).
3. Port Swift and Kotlin/Java changes. The bridge parts that differ are `AdMobPlugin.swift` / `AdmobPlugin.kt` +
   `AdMob.java` (the entry points), `PluginCall.swift` / `PluginCall.kt` and the banner's parent view on Android.
4. A new method: add it to `build.rs` (`COMMANDS`), `src/commands.rs`, `guest-js/commands.ts`,
   `permissions/default.toml`, and the Swift and Kotlin plugins. `cargo build` regenerates
   `permissions/autogenerated/`.
5. Run `npm run verify`, `cargo test`, the Android unit tests, and the iOS check (see README, Testing).
6. Raise the version (`Cargo.toml`, both `package.json`); merging to `develop` tags it (`auto-tag.yml`).

## When the SDKs are newer than upstream's pins

Upstream pins an exact Google Mobile Ads iOS version. We follow upstream's pin rather than moving ahead of it, so
that the native code we copied is the code upstream tested. If an app needs a newer SDK, raise the pin in a fork or
open an issue.
